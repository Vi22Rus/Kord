# Требования к движку Kord

Документ ведётся по отдельным механизмам. Статусы аудита не означают, что код изменён.

## PR-PR-01 — Сквозная трёхзначная логика (true / false / nil)

**Область:** данные игрока, цели, аур, предметов и все условия движка.

### Требование

Все проверки, в которых возможна неопределённость, обязаны различать:

| Значение | Значение состояния |
|---|---|
| `true` | Условие достоверно выполнено |
| `false` | Условие достоверно не выполнено |
| `nil` | Состояние неизвестно, данные недоступны или их нельзя безопасно прочитать |

Нельзя автоматически превращать `nil` в `false`, в ноль или в отсутствие эффекта. Если движок не смог прочитать дебаф цели, это не доказывает отсутствие дебафа; неизвестное число предметов не равно нулю.

Трёхзначная семантика должна сохраняться на всём пути: чтение API → провайдеры данных → вычисление условий → логические операции → выбор приоритета → проверка возможности применения способности. `AND`, `OR`, `NOT` должны корректно обрабатывать неизвестность (в частности, `false AND nil = false`, `true OR nil = true`, `NOT nil = nil`). Если неопределённое условие более высокого приоритета может изменить итоговый выбор, нельзя молча пропускать его и рекомендовать следующий приоритет как достоверный. Окончательное `READY` должно подтверждаться проверкой пригодности способности, а не одним лишь условием профиля.

### Референсы — предварительные наблюдения

- **Sonah:** отмечено различение `false` и `nil` для аур и предметов. Указанные для последующей построчной проверки места: `Sonah/Core/Atoms/Auras.lua` (`ReadApi`), `Sonah/Core/Atoms/Items.lua` (`Items.Count`). Потенциальный образец провайдеров данных.
- **Rotation Master:** отмечены проверки доступности данных, защита от нечитаемых значений и причины неопределённости. Указанное место для проверки: `RotationMaster/Core/conditions.lua` (`switchUnitWitness`). Потенциальный образец оценки условий.
- **MaxDps:** встречаются `true`, `false` и `nil`, но это само по себе не подтверждает единую сквозную трёхзначную модель. Указанное место для проверки: `MaxDps/Helper.lua`. Не выбирать основным образцом без дальнейшей проверки.

**Ограничение доказательности:** перечисленные наблюдения перенесены из предварительного отчёта; в рамках данного требования не зафиксированы построчные выдержки исходников референсов. Поэтому это направления для проверки, а не доказательство полноты их реализации.

4. Добавить диагностический вывод причины `UNKNOWN` и тесты для чтения данных, логических комбинаций и остановки приоритетов.
