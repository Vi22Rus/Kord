## Архитектурное правило — общеклассовое ядро (сквозная ревизия PR/PL/SP)

**Обязательно для всех требований, P0 на уровне архитектуры.** KordRotation и KordRotationDevTools остаются двумя аддонами с общими каноническими контрактами. Все общие игровые факты и проверки — **одна реализация для всех классов**: GameAPI, наблюдения, AbilityEligibility, условия, кэш и диагностика. Никаких отдельных `HunterRangeObservation`, `MageSpellCost`, `PaladinMeleeCheck` и т. п. для одной и той же операции. Классовые особенности задаются **данными/ID/правилами профиля** в общем провайдере; только при доказанной несовместимости API допустим маленький адаптер, не дублирующий универсальный движок. Новое имя `*Observation` в аудите обозначает **логический контракт**, а не требование создавать отдельный Lua-файл: предпочтительно расширять существующий общий модуль. Число файлов не должно расти из-за каждого класса, способности или требования.
