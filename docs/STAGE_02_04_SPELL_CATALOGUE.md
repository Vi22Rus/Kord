# Этап 2.4 — каталог изученных способностей, ранги и изменение книги

**Версия:** 0.1.8.3-rc3. **Реализовано в коде; игровое тестирование WoW Forever не проводилось.**

## Контракт

`KR.SpellCatalogue:Read(force)` возвращает `{status="ready"|"unavailable", reason?, method?, revision, observedAt?, entries={...}}`. Сохранены поля прежнего редактора `id`, `name`, `texture` и `status="ready"`; добавлены `rank`, `rankNumber?`, `displayName`, `source`, `known=true`. Поле `rank` — строка от игрового API, число ранга извлекается только при очевидном цифровом суффиксе. Неизвестный ранг не угадывается и не меняет идентификатор способности.

**Стабильный ключ — spellID.** Одинаковые имена с различными ID сохраняются отдельно (разные ранги); повторный ID в нескольких слотах книги дедуплицируется. Нет заранее сочинённой базы всех заклинаний. `Filter` поддерживает поиск по отображаемому имени, рангу и ID, категории и настройкам редактора; пользовательские настройки по ID не мигрируются и не теряются.

## Выбранные API и fallback

1. **Legacy**: `GetNumSpellTabs` → `GetSpellTabInfo` (offset/count) → `GetSpellBookItemInfo` (type/ID) → `GetSpellBookItemName` (name/rank) с fallback `GetSpellInfo`; `GetSpellBookItemTexture` с fallback `GetSpellTexture`. Везде `pcall`, allowlist GameAPI и ограничение размеров.
2. **Modern** при невозможности достоверно прочесть legacy: `C_SpellBook.GetNumSpellBookSkillLines` → `C_SpellBook.GetSpellBookSkillLineInfo` → `C_SpellBook.GetSpellBookItemInfo` с `Enum.SpellBookSpellBank.Player` и `Enum.SpellBookItemType.Spell`; имя/иконка из C_SpellBook с fallback `C_Spell.GetSpellInfo`. Поля таблиц проверяются перед использованием. Не предполагается, что современный банк применим к любой версии Forever.
3. `KR.GameAPI:ReadValues` — новый ограниченный read-only адаптер многорезультатных API (до 6 значений). Отсекает ошибки вызова, проверяемые secret и NaN/Infinity. Структурированная современная запись дополнительно проверяется на доступность полей через `pcall`. Отсутствие в клиенте `issecretvalue` НЕ означает доказанную безопасность значения.

**Не допускать частичного каталога:** если слот/ранг/ID/имя повреждены или структура неизвестна, не публиковать уже прочитанные элементы как `ready`. Возвращать `unavailable` с пустым entries и явной причиной. При нулевом подтверждённом количестве элементов — `ready` с причиной `spellbook_empty`.

## Обновление и производительность

- `Initialize()` подписывает каталог на `spellbook`, `talents`, `identity`; `Invalidate(reason)` помечает кэш устаревшим.
- В EventBus добавлены `LEARNED_SPELL_IN_TAB`, `SKILL_LINES_CHANGED`; ранее уже были `SPELLS_CHANGED`, `PLAYER_TALENT_UPDATE`, `TRAIT_CONFIG_UPDATED`, `ACTIVE_TALENT_GROUP_CHANGED`, `PLAYER_ENTERING_WORLD`.
- `GetSnapshot()` сравнивает ревизии каналов непосредственно, даже до их `Flush()`; `Read()` использует 2-секундный TTL и возвращает копию, чтобы UI не мог испортить кэш.
- Ограничения предотвращают бесконечный обход: максимум 40 секций, 800 проверенных слотов и 2500 записей (последнее число является дополнительной страховкой). При превышении — `unavailable`, не обрезанный «успешный» каталог.
- При изменении набора заклинаний редактор выполняет явный `Read()` по кнопке пересканирования; автоматическая инвалидация не ломает существующий UI или профиль.

## Качество и границы

- В проект добавлен `tests/stage_02_04_spell_catalogue.lua`: реальные mock-сценарии legacy и modern, ранги, одинаковые имена, повторные ID, обучение/исчезновение, ошибки API, неизвестный bank, изоляция кэша.
- Проверки синтаксиса Lua и запуск mock-теста необходимо фиксировать отдельно как PASS/FAIL/NOT RUN. Совместимость с конкретным игровым клиентом не подтверждена.
- Ни одно заклинание не кастуется. Нахождение в книге НЕ разрешает рекомендацию: в 2.5 обязательно подтверждать размещение на штатной панели Blizzard, затем в 2.7 — пригодность к применению.
- Дальше **2.5** — сканирование Blizzard action slots, страниц, форм и макросов; реальные клавиши — этап 2.6.
