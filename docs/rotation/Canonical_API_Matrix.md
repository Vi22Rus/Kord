## Как читать

Каждая строка — самостоятельная возможность API, операция получения данных или сценарий использования, выявленный в источниках. Колонки референсов показывают **имеющиеся в предыдущем аудите указания на исходники**, а не гарантированно работающие методы. `—` = нет зафиксированного доказательства; `(audit)`, `(review required)` и `уточнить` = не проверены точная сигнатура/вызов/связь с профилем. Кандидатный механизм **не является окончательно подтверждённым**. Последний столбец хранит исследовательский вывод, а не архитектурное решение для текущего движка. Записи о дебаг-коде и общих библиотеках не считаются подтверждением использования в ротации. Игровой тест: **NOT RUN**.

## Проход 9: JustAC zero-gate и границы диапазонов — повторная проверка ZIP

- `JustAC/BlizzardAPI/SecretValues.lua:110–165,169–236`: `IsSecretZero(v)` возвращает `true` для нуля, `false` для ненуля, `nil` при недоступности; `v==nil` отдельно считается нулём (поэтому вызывающий `EvaluateBelow` предварительно отбрасывает `result==nil`). - `JustAC/BlizzardAPI/StateHelpers.lua:622–669`: проценты нормализуются до 0.1%, ограничиваются 0–100; пороговая `Linear` curve имеет рампу ±0.1 процентного пункта (eps=0.001 на домене 0–1), с 100 ниже и 0 выше. **Матрица определяет будущую архитектуру, а не наоборот.** Нельзя выбирать, сокращать, ранжировать или отвергать возможности API по текущим потребностям, ограничениям либо реализации `RotationEngine`. Исследование охватывает все выявленные в шести референсах механизмы, даже если сейчас они не нужны ни одному профилю. Полнота источников и доказательств важнее удобства реализации. Разработка и подгонка движка — **отдельный последующий этап** после завершения и утверждения матрицы.

Названия исторических колонок «Потребность профиля» и «Выбор Kord / статус» сохранены для стабильности 101-строчного реестра; читать их соответственно как «Возможность/сценарий» и «Доказательства, ограничения, статус». Старые фразы «Kord:», «Выбор:» и упоминания движка в строках не являются решениями о проектировании. При последующих проходах формулировать выводы **только** в терминах API, свидетельств, ограничений и проверки.

**Следующий проход:** аудит неполных ссылок и статусов по всем шести архивам без отбора «нужных движку» порогов. Исторический LazyG — иллюстрация пользовательского опыта, **не** нормативный седьмой референс.
