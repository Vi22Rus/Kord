## Воспроизводимый протокол вручную в клиенте

Перед проверкой записать клиент/версию Forever, дату, персонажа, ID предмета, скриншот инвентаря, количество в сумках, наличие такого же предмета в банке/экипировке и состояние боя. Не использовать реальные приватные данные в общем отчёте. Открыть чат в игре и выполнять **по одной** команде `/run`; это диагностические вызовы без действия предмета.

1. Наличие функций:
   ```lua
   /run print("IT01 API",type(C_Item),type(C_Item and C_Item.GetItemCount),type(GetItemCount),type(issecretvalue))
   ```
   Если функции нет, отметить `API MISSING`, остальные вызовы не выполнять.
2. Для известного itemID, лежащего в обычных сумках, диагностировать доступность вызова:
   ```lua
   /run local f=C_Item and C_Item.GetItemCount;if type(f)=="function" then local ok,v=pcall(f,5512,false,false);print("IT01 CALL",ok,ok and type(v) or "ERROR") end
   ```
   `5512` — только пример ID; заменить на реально проверяемый ID. Наличие числового типа **не доказывает** ни область хранения, ни безопасное вычисление значения.
3. После подтверждения наличия `issecretvalue` (или соответствующего проверенного клиентского средства) выполнить аналогичную проверку secret; не приводить неизвестное/секретное значение к строке, не сравнивать его с нулём и не выполнять арифметику над ним.
4. Только для безопасного и подтверждённого числового результата сравнить значения `(itemID,false,false)`, `(itemID,true,false)` и `(itemID,false,true)` при неизменном инвентаре. Отметить аргументы и фактические значения, не предполагать заранее смысл третьего аргумента.
5. В контролируемых условиях проверить: 0 везде; 1 в сумке; несколько стаков в разных сумках; предмет только в банке; только в экипировке; при открытом/закрытом банке; в бою и вне боя. Отдельно проверить `nil`, ошибку и запрещённый/secret результат, если они реально воспроизводятся. Сравнение `includeBank` при отсутствии предмета в банке не подтверждает его семантику.
6. Если чтение не даёт подтверждённой картины BAGS_ONLY, **не активировать** его в GameAPI или GameState. Следующий путь — клиентская валидация одного `C_Container` bag snapshot в шаге 1.3.
