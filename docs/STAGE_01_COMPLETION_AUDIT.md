- При инспекции `MainWindow.lua` обнаружено, что вкладка `advanced` была зарегистрирована в меню, но попадала в `makePlanned`. Исправлен маршрут до `KR.Pages:Advanced`.

- **Не проверено в игре:** сохранения, реальная совместимость методов Frame и поведение при событиях Forever.

## Регрессия сохранений 0.1.7.6 (статически реализовано)

## Открытые пункты ТЗ перед общим пользовательским QA
1. **Фирменный логотип — исправлено в коде 0.1.7.4, не проверено в игре:** в `KordRotation/Media/Logo.blp` добавлен ранее подготовленный логотип KR/Kord Rotation в BLP2 64×64; Главная теперь отображает его вместо «KR» и Unicode-стрелок. Декодирование и контроль SHA прошли, но визуально проверить его в WoW Forever при общем QA всё равно необходимо.
2. **Частично закрыто в исходниках 0.1.7.1:** showInCombat/showOutOfCombat/requireTarget/hideWhenDead/hideMounted через API и события. **Полная панель/слои:** **Частично закрыто в 0.1.7.2:** независимые слои клавиши/названия/кулдауна/зарядов/затемнения/GCD и их переключатели реализованы, значения только из явного SetDisplayData, без выдуманных боевых данных. **Открыто:** достоверный адаптер Spell ID/cooldown/charges/GCD и binding API (часть этапа 2), варианты цвета/позиции каждого текста, подсветка/анимация, защищённое изменение в combat lockdown. Отдельные контролы базовой видимости добавлены, но не проверены в игре. Не реализована очередь защищённых изменений в combat lockdown. Реальная логика часть этапа 2, но UI должен честно показывать контроль доступности.
3. **Частично закрыто в исходниках 0.1.7.1:** быстрые тумблеры будущих рекомендаций, панели/теста/блокировки и переход к «Отображение» добавлены. **Открыто:** подробный статус режима целей и защиты, кнопка явного теста UI/управление перемещением без slash-команд, итоговый рендер в игре.
4. **Дополнительно:** кнопка миникарты и подсказки пока только настройки без реализации; производственные частоты scheduler не подключены (этап 2). Если потребуются именно рабочие контролы внутри этапа 1 — доделать, либо явно исключить из acceptance scope с согласованием.
5. **Диагностика:** API наличие и журнал есть, но ещё не все тесты фактической доступности keybinding/actionbar/protected режимов, нет полноценной фиксации Lua-ошибок извне. Добавлять защитные probes, не выполнять непроверенные защищённые действия.
6. **Надёжность:** не запускались Lua syntax/parser и автоматические unit tests на всех модулях, не проверялись сохранение/миграции, граничные размеры UI, reset и совместимость со всеми классами.
7. **SpellBook и локали:** конкретный API WoW Forever и полное соответствие текстов игровой верстке остаются неподтверждёнными.
8. **Профили:** в 0.1.7.3 исправлено сохранение всех параметров слоёв, применение Classic после удаления активного профиля и удаление зависших привязок. **Осталось:** тест смены веток и пользовательского удаления в WoW Forever.

## Следующее действие разработки
**Не приглашать пользователя немедленно тестировать 0.1.7.** Прежде закрыть необходимые для приёмки отсутствующие UI-элементы и сделать повторный статический аудит отдельным коммитом со своим CHANGELOG. Если для какого-то элемента нужен недоступный игровой API, сохранить явное состояние «не поддерживается», но не обещать скрытую реализацию. Затем собрать единый release candidate и предоставить чек-лист `docs/STAGE_01_QA_PLAN.md` (44 кейса); только тогда запускать единый игровой тест.
