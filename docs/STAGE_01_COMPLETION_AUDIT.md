# Аудит полноты первого этапа — после кода 0.1.7

Сверено с полным `docs/STAGE_01_INTERFACE.md`. **Завершение нумерованных подшагов не равно выполнению всех пунктов ТЗ и не равно пользовательской приёмке.**

## Подготовлено исходниками
- Главный экран Modern Dark, девять зарегистрированных страниц и их содержимое, часть реальных сохраняемых контролов.
- Определение класса/ветки, подтверждено пользователем в 0.1.1 только на охотнике 30 уровня (21/0/0).
- Шесть языков, русский подтверждён пользователем в 0.1.1.1; другие языки ещё не проверены.
- Отдельная тестовая панель 1–5 слотов и настройки внешнего вида.
- Настройки будущих ротаций и карты способностей по CLASS_TREE_N/Spell ID; чтение книги заклинаний feature-detected, не проверено на клиенте.
- Предпочтения индикаторов и пресеты оформления, расширенная диагностика и безопасные сбросы.
- История изменений для каждого отдельного коммита.

## Открытые пункты ТЗ перед общим пользовательским QA
1. **Фирменный логотип:** утверждённый изображением KR ещё НЕ внедрён в WoW-совместимую текстуру; текстовая замена — временная. Нужна проверенная TGA/BLP.
2. **Полная панель/слои:** не завершены настраиваемые текст клавиши/названия, cooldown/charges/dimming/GCD, независимые текстовые слои; боевые данные НЕ выдумывать. Не хватает отдельных контролов видимости в бою/без цели/смерти/на маунте и поведения очереди изменений в combat lockdown. Реальная логика часть этапа 2, но UI должен честно показывать контроль доступности.
3. **Главная:** не все тумблеры и кнопки §1.4 реализованы (быстрое включение будущих рекомендаций, переход на страницу отображения, статус режима целей и защиты).
4. **Дополнительно:** кнопка миникарты и подсказки пока только настройки без реализации; производственные частоты scheduler не подключены (этап 2). Если потребуются именно рабочие контролы внутри этапа 1 — доделать, либо явно исключить из acceptance scope с согласованием.
5. **Диагностика:** API наличие и журнал есть, но ещё не все тесты фактической доступности keybinding/actionbar/protected режимов, нет полноценной фиксации Lua-ошибок извне. Добавлять защитные probes, не выполнять непроверенные защищённые действия.
6. **Надёжность:** не запускались Lua syntax/parser и автоматические unit tests на всех модулях, не проверялись сохранение/миграции, граничные размеры UI, reset и совместимость со всеми классами.
7. **SpellBook и локали:** конкретный API WoW Forever и полное соответствие текстов игровой верстке остаются неподтверждёнными.
8. **Профили:** интерфейс позволяет привязать оформление, но сложные случаи переключения спецификаций/удаления связанных пресетов ещё не проверены.

## Следующее действие разработки
**Не приглашать пользователя немедленно тестировать 0.1.7.** Прежде закрыть необходимые для приёмки отсутствующие UI-элементы и сделать повторный статический аудит отдельным коммитом со своим CHANGELOG. Если для какого-то элемента нужен недоступный игровой API, сохранить явное состояние «не поддерживается», но не обещать скрытую реализацию. Затем собрать единый release candidate и предоставить чек-лист `docs/STAGE_01_QA_PLAN.md` (44 кейса); только тогда запускать единый игровой тест.
