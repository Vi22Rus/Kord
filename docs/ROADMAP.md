## Этап 2 — ядро игровых данных: подробный план (PLANNED)

**Цель:** построить проверяемое, устойчивое к отсутствующим API ядро получения состояния игры и выдачи **данных** о допустимых рекомендациях. Этап 2 НЕ означает готовую боевую ротацию: первое содержательное правило приоритетов и живой ротационный профиль относятся к этапу 3.

**Обязательные принципы:**
- Только штатный публичный API WoW Forever с проверкой существования, типа возвращаемых значений и фактического поведения; ни секретные/защищённые данные, ни защищённые действия не обходить.
- Никаких автоматических нажатий, передачи команд в Windows, RGB-сигналов, специальных пиксельных индикаторов, скрытого экспорта рекомендаций или доступа к внешним программам. Аддон показывает рекомендации игроку.
- **Жёсткий допуск:** способность-кандидат должна быть подтверждена на разрешённой панели действий Blizzard. Наличие в книге заклинаний само по себе недостаточно. Неизвестное состояние => не рекомендовать (fail closed).
- Система рекомендаций пропускает отсутствующую на панели, неподтверждённую либо непригодную способность и рассматривает следующего кандидата по приоритету. Если допустимых нет, возвращает пустой результат, а не тестовую заглушку. При нескольких слотах одного заклинания — детерминированный выбор.
- Привязки клавиш определяются через реальные API биндов и слотов. При отсутствии привязки показывается рекомендация без подписи клавиши **только если** слот достоверно существует; отсутствие клавиши не означает отсутствие способности.
- Внутренние ID/коды не должны разрушать отображение нормальных иконок, локализацию, поддержку рангов и возможность диагностики. Маскировку ID считать только повышением порога анализа, а не антибот-защитой.
- Сохранить текущие интерфейс, девять вкладок, параметры и профили; новые UI-строки и уникальные подсказки — на шести языках; без ложных утверждений о проверке в клиенте.
