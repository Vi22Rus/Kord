# PROJECT_CONTEXT — постоянный контекст Kord Rotation

> Читать в начале **каждого нового чата и перед каждым изменением кода** вместе с `AGENTS.md`, `docs/ROADMAP.md`, `docs/STAGE_01_INTERFACE.md` и `CHANGELOG.md`.

## Что строим
**Kord Rotation** — собственный модульный Lua-аддон **рекомендаций** следующей способности для WoW Forever. Не бот/автонажатие. Классический замысел: 9 классов по три ветки талантов = **27 ротационных профилей**. Поддержка DPS, танков и хилов требует разных правил, не единой DPS-функции. Название в интерфейсе «Kord Rotation», кодовая папка `KordRotation`, Lua-префикс `KR`, команда `/kr`. Не называть проект LazyRotation, LazyG или Kord_Rotation.

## Автоматизация выбора
НЕТ выпадающего списка всех классов. Получить токен класса из API персонажа; подсчитать вложенные очки в трёх ветках талантов и выбрать ветку с максимальным числом. При ничьей — ранее подтверждённая из лидирующих, затем согласованный ответ API клиента, иначе статус «не определено». Пустые/недоступные данные обрабатываем безопасно. Обновлять по событиям смены талантов/набора/входа.

## Этапы и текущий статус
**Текущий этап: 1 — интерфейс и фундамент.** Существует код 0.1.1 (0.1.0 проверен пользователем): TOC, SavedVariables, Modern Dark UI, окно с 9 пунктами навигации и slash-команды. **0.1.0: пользователь проверил окно и 9 вкладок без ошибок; 0.1.1: пользователь подтвердил охотника 30-го уровня, 21/0/0, header_groups, Beast Mastery, confirmed; 0.1.1.1 локализация НЕ ПРОВЕРЕНА на разных клиентах.** Автоматическое определение использует C_Traits, секции по groupIDs, резервное пространственное разделение (требует подтверждения). Игровой логотип пока временно представлен текстовой областью KR; утверждённые растровые референсы не подключены к WoW. Не выдавать готовность функций без реализованных файлов, коммитов и результатов теста. Полный подробный план — `docs/STAGE_01_INTERFACE.md`; краткие будущие этапы — `docs/ROADMAP.md`.

## Две части интерфейса
1. Боевая панель: 3 рекомендуемые иконки, первая крупнее; настраиваемые 1–5 слотов, направление, размеры, расстояние, alpha, рамки, текст клавиш, drag/lock/visibility; дополнительные защиты, прерывания, ресурсы при поддержке API.
2. Окно настроек с 9 страницами: Главная, Отображение, Ротация, Способности, Индикаторы, Профили, Дополнительно, Диагностика, О проекте. Первая страница показывает автоматическое определение класса/ветки и состояние профиля. Никакого ручного выбора всех 9 классов.

## Архитектура
Lua addon + `.toc`, SavedVariables `KordRotationDB` и `KordRotationCharDB`. Отдельные модули `Core/Character`, `Core/Talents`, `Core/SpecDetector`, `Core/Capabilities`, `Core/Settings`, `UI/RotationDisplay`, `UI/SpellIcon`, `UI/MainWindow`, `UI/Pages`. Модули ротаций разрабатываются только после стабилизации UI/API-контракта.

Интерфейс получает список Spell ID и визуализирует рекомендации; не вычисляет правила сам. Способности хранятся по Spell ID, профили по токенам класса/ветки. Разделять ротационные профили и профили оформления.

## Игровые ограничения и проверка
WoW Forever может иметь нестандартный/современный API и ограничения защищённых боевых данных. `GetTalentInfo`, `GetNumTalentTabs`, `C_ClassTalents`, `C_Traits` и прочее нельзя объявлять совместимыми без теста на конкретной версии. Не выдавать прогноз 2–3 следующих способностей за гарантированную последовательность, когда будущие условия не наблюдаемы. Различать «API существует», «вызов успешен», «данные доступны в бою». Изменения защищённых UI-элементов откладывать до выхода из боя, если нужно.

## Референсы
В проекте приложены `Sonah.zip` и `JustAC.zip`. Использовать как **референсы**, не копировать код вслепую: изучить лицензию, дерево файлов и совместимость API перед переносом решений. Предыдущая проектная беседа определила желаемые UI-страницы; это ТЗ, а не доказательство их работоспособности.

## Локализация (обязательное архитектурное правило)
- В `Core/Locale.lua` зарегистрированы словари для `ruRU`, `enUS/enGB`, `frFR`, `deDE`, `ptBR/ptPT`, `esES/esMX`. Выбор — `GetLocale()`; неизвестная локаль => английский. Системные токены класса, профиля, статус и Spell ID **не локализуются**, только UI-строки.
- Любая следующая вкладка/кнопка/сообщение обязана получать текст из `KR:L(KEY)` или `KR:Format(KEY,...)`; не писать русские или английские пользовательские строки непосредственно в Lua UI. Добавлять новые ключи во все словари.
- Названия веток в UI получают через `KR:GetLocalizedTree(classToken,index)`, класс — через локализованный `UnitClass`. Коды `HUNTER_TREE_1`, `header_groups` и т. п. остаются в диагностике, но подписи статусов переводятся.
- Русский пользователь сообщил, что символ-разделитель между названием класса и веткой отображается квадратом. Он заменён на обычный ASCII-дефис. Графические референсы и бренд `Kord Rotation` не переводятся.
- Корейский/китайский клиенты пока получают английский fallback, пока для них нет проверенных переводов/шрифтов.

## Рабочие решения
- Интерфейс разрабатывается **первым**, включая автоматический детектор класса/ветки как необходимую его часть.
- Реальные правила ротаций — после UI и проверки API.
- Неподключённые функции показывать с понятной пометкой «планируется/недоступно», не имитировать рабочее состояние.
- Не нарушать правила игры через скрытое управление персонажем; аддон рекомендует, игрок нажимает сам.
- Под каждый коммит обязательно готовить подробный `CHANGELOG.md`, следовать `docs/CHANGELOG_RULES.md` и `AGENTS.md`.
- Ошибки пользователя не игнорировать: связать отчёт тестера -> гипотеза -> подтверждённая причина -> исправление -> повторный тест и статус.
