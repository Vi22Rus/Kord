# Этап 1 — интерфейс Kord Rotation (подробное ТЗ)

**Статус:** IN PROGRESS — 0.1.0 проверен пользователем; 0.1.1 (HUNTER/BM, 21/0/0) проверен пользователем; 0.1.1.1 русская локаль подтверждена пользователем; прочие не проверены; 0.1.2 тестовая боевая панель подготовлена и ожидает проверки. **Объём:** UI и фундамент; 27 боевых ротаций не входят в этот этап. **Референсы:** `Sonah.zip` и `JustAC.zip` в материалах проекта — перед заимствованием конкретных решений открыть исходники, установить версию, лицензию и подтверждённые API. Ни одно утверждение о совместимости не считать проверенным без запуска на Forever.

### Статус 0.1.0 и зависимость от графических файлов
Первый коммит исходников создаёт базовое окно, навигацию, сохранение позиции и команды, но **не реализует** детектор специализации, очередь рекомендаций, контролы всех вкладок и боевые индикаторы. Девять страниц присутствуют как структура; кроме «Главная»/«О проекте» это честные заглушки. Область фирменного знака — временный текст KR/KORD ROTATION; утверждённые эталонные JPEG не подходят для игрового UI напрямую. До реального логотипа нужны прозрачные TGA/BLP, проверенные в клиенте. Отклонённые SVG не использовать.

### Прогресс 0.1.2
Добавлены три **тестовые** слота (72/52/52 пикселя, зазор 6, отдельный ярлык теста), перемещение при разблокировке, сохранение позиции и восстановление после /reload, режим по умолчанию скрыт и заблокирован, команда /kr test и кнопки на Главной. Используется системная иконка вопросительного знака, **не Spell ID**. Игровые иконки и настоящая очередь рекомендаций остаются в следующих этапах; панели обороны и прерывания не заявлены как готовые. 0.1.2 ещё не проверена на Forever.

### Локализация как правило для всех следующих сборок
0.1.1.1: автоматический выбор языка через `GetLocale()`, словари `ruRU, enUS, frFR, deDE, ptBR, esES`, алиасы `enGB, ptPT, esMX`, неизвестные языки => английский. UI, команды/диагностика и названия веток должны ссылаться только на словарные ключи, но внутренние класс- и профайл-токены не меняются. При добавлении страниц обязательны переводные строки во всех шести языках. Корейский/китайский — будущие переводы, английский fallback. Подтверждённый тест охотника: уровень 30, 21/0/0, `header_groups`, `confirmed`, Beast Mastery; предварительная проверка одного класса, не всех 27. Исправлена проблема отсутствующего глифа `·` при отображении названия класса: ASCII дефис.

## 1.0 Цель и решения, которые нельзя потерять
- Название на экране **Kord Rotation**, идентификатор папки **KordRotation**, префикс **KR**, команда **/kr**.
- 9 классов × 3 ветки = 27 будущих профилей. Интерфейс автоматически определяет **класс** и **ведущую ветку талантов**; выбор одного из девяти классов вручную НЕ нужен.
- Первая итерация создаёт интерфейс с тестовыми иконками, работающие настройки и контракт с движком. Нельзя выдавать тестовую рекомендацию за боевую.
- UI никогда не запускает игровые заклинания автоматически; это помощник рекомендаций. Боевые данные Forever могут быть защищены/недоступны — каждую функцию проверять в самом клиенте.
- Две независимые области: компактная **боевая панель** и **окно настроек** с боковой навигацией.

## 1.1 Определение персонажа и ведущей ветки
1. При `PLAYER_LOGIN` после готовности клиента получить класс через `UnitClass("player")`; использовать стабильный токен (например `WARRIOR`), не локализованное имя. Получить уровень.
2. Чтение талантов реализовать за адаптером `Talents.lua` с проверкой возможностей клиента (включая `C_ClassTalents`, `C_Traits`, `C_SpecializationInfo`, если они существуют). Не считать старые `GetTalentInfo`/`GetNumTalentTabs` доступными без проверки. Выяснить сопоставление узлов трём деревьям и число **вложенных рангов**, не количество разблокированных узлов.
3. Суммировать очки в каждой из 3 веток. Максимум = активная ветка. Пример 31/20/0 => «Оружие». Данные о текущей специализации клиента, если имеются, выводить отдельно от результата по очкам.
4. Ничья: сохранять ранее *подтверждённую* ветку, если она в числе максимумов; иначе использовать надёжное подтверждение от клиента, если оно согласуется с деревьями; иначе статус «не определена», без произвольного выбора.
5. Ноль очков, нет конфигурации, временно скрытые данные, несовместимый API => явно показать «ожидание/не определено/недоступно», без ложного распознавания. Если была ранее подтверждённая ветка, показывать её лишь с пометкой «не подтверждена».
6. После изменения талантов/активной конфигурации, входа, смены уровня и релевантных событий пересчитать ветку, дождаться готовых данных. Не опрашивать таланты каждый кадр.
7. Интерфейс получает событие `SPEC_CHANGED` (внутреннее), обновляет заголовок, профиль ротации и относящиеся к ветке настройки.
8. Тестирование минимум на всех 9 классах/трёх ветках, плюс пустые таланты, ничья, пересброс, переключение набора, ошибки API. Если нет живого персонажа, отметить тест как НЕ ПРОВЕДЁН.

## 1.2 Боевая панель
- По умолчанию 3 слота: главная иконка 72 px, 2 следующие по 52 px, промежуток 6 px, ряд слева направо. Настраиваемый диапазон слотов 1–5; до появления достоверного планировщика будущих действий дополнительные слоты могут быть пустыми, а не выдуманными.
- Первая иконка визуально выделена; последующие — второстепенные. Настоящая игровая текстура по Spell ID. На старте — **явный тестовый режим** с индикатором «ТЕСТ».
- Иконка: текстура, рамка, текст клавиши, индекс очереди, опциональное название, таймер восстановления, заряды, затемнение недоступности, GCD-оверлей, цветовая подсветка. Каждый слой включается отдельно; боевые значения только если API достоверен.
- Опциональные независимые области: защиты (1–3 иконки), прерывания (отдельный индикатор), ресурсов (полоса). По умолчанию выключены; их расчёт подключается позднее.
- Реакция на смену Spell ID не должна создавать новый Frame без нужды; обновляем текстуру/текст/слои. Пустой слот безопасно очищается.
- Режим тестового отображения доступен вне зависимости от отсутствия готовой ротации; реальный режим показывает «нет профиля», а не фиктивную очередь.

## 1.3 Основное окно настроек
- Единое перемещаемое окно с заголовком **Kord Rotation**, версией, статусом персонажа и кнопкой закрытия.
- Слева фиксированный список страниц, справа прокручиваемый контент, общие элементы управления (toggle, slider, dropdown, checkbox, editbox, searchable list, tooltip, confirmation dialog).
- Команды `/kr` — открыть/закрыть; `/kr config` — открыть настройки; `/kr test` — переключить тестовую панель; `/kr resetposition` — восстановить положение; `/kr debug` — диагностика (точный синтаксис зафиксировать и проверить в игре).
- Девять страниц (в таком порядке): **Главная**, **Отображение**, **Ротация**, **Способности**, **Индикаторы**, **Профили**, **Дополнительно**, **Диагностика**, **О проекте**.
- Конкретная страница создаётся лениво при первом открытии; общие элементы не реализуются заново в каждой вкладке. При переключении сохраняется состояние и не регистрируются повторные обработчики.

## 1.4 Вкладка «Главная»
**Блок персонажа:** класс, уровень, ветка, способ определения, 3 суммы очков, активный ротационный профиль, подтверждённость определения, статус профиля («активен», «выключен», «в разработке», «ошибка»).

**Управление:** независимые тумблеры «Включить рекомендации», «Показывать панель», «Заблокировать панель», «Тестовый режим». Выключенный ротационный движок не обязательно скрывает UI, а скрытый UI не обязательно отключает диагностику.

**Состояние:** режим целей (авто/ST/AoE), атакующие/защитные рекомендации, индикаторы; без утверждений о работе неподключённых модулей.

**Кнопки:** «Переместить панель», «Проверить интерфейс», «Настройки отображения», «Сбросить положение». Быстрые действия используют те же Settings API, что и остальные вкладки.

## 1.5 Вкладка «Отображение»
### 1.5.1 Положение
- Перетаскивание вкл/выкл, блокировка по умолчанию ВКЛ.
- Точка привязки: центр экрана (база); к игроку/цели — лишь при поддержке конкретных UI-фреймов.
- X=0, Y=-120 по умолчанию, сохранение точки привязки, координат и масштаба.
- «Сброс позиции»; защита от выхода за границы экрана после смены разрешения/UI scale.
- При перетаскивании показывать контур/подсказку; сохранять координаты после отпускания.

### 1.5.2 Размер и раскладка
| Параметр | Диапазон | Старт |
|---|---|---|
| Основная иконка | 32–128 px | 72 |
| Дополнительные | 24–96 px | 52 |
| Число слотов | 1–5 | 3 |
| Межиконный промежуток | 0–30 px | 6 |
| Масштаб панели | 50–200% | 100% |
| Направление | горизонтально/вертикально | слева направо |
| Место главного слота | начало/конец | начало |

Вертикальная ориентация и порядок обратного направления — отдельные значения, чтобы «вертикально» и «сверху вниз» не дублировались.

### 1.5.3 Внешний вид
- Общая прозрачность 0–100%; отдельная прозрачность второстепенных иконок.
- Фон вкл/выкл; цвет и alpha фона.
- Рамки: стандарт/минимализм/нет; толщина 0–4 px.
- Цвет/яркость подсветки основной иконки, простая анимация смены (только если подтверждена производительность и возможности).
- Скругления только при реальной поддержке текстур/9-slice, иначе корректный fallback.

### 1.5.4 Тексты и таймеры
- Текст клавиши, индекс позиции, название способности, оставшееся восстановление, заряды; каждый тумблер отдельно.
- Размер, цвет, тень, позиция текста.
- Горячую клавишу получать из существующих ActionButton/bindings по разрешённому API; несколько назначений — детерминированный выбор; отсутствие — пусто или «—», не придумывать.

### 1.5.5 Условия видимости
| Контекст | Варианты |
|---|---|
| Бой/вне боя | показать/скрыть |
| Есть цель/нет цели | показать/скрыть |
| Верхом | скрыть/оставить |
| Персонаж мёртв | скрыть/оставить |
| Стандартный UI скрыт | следовать игровому UI |
| Нет ротационного профиля | скрыть/показать статус |
| Тестовый режим | принудительный показ с меткой |

Приоритеты: ручное отключение панели > безопасное скрытие с UI > тестовый режим (кроме ручного отключения) > контекстные правила. Зафиксировать порядок и покрыть тестами. Старт: в бою показывать, при смерти/верхом скрывать, вне боя — при подходящей цели или тестовом режиме.

## 1.6 Вкладка «Ротация»
**Профиль:** автоматически вычисленная цепочка CLASS + TREE -> profile ID; статус («не написан» не маскировать под «работает»), версия, очки талантов, режим.

**Режим целей:** Auto/ST/AoE, вручную закреплённый режим имеет приоритет. Если автоопределение числа противников на Forever недостоверно, честно сообщать об ограничении и разрешать ручной выбор.

**Категории использования:** основные атакующие, длинные кулдауны, усиления, расовые, аксессуары, расходники, защитные, прерывания, мобильность; по умолчанию защитные и прерывания отдельны от DPS-очереди.

**Условия:** кулдауны только в бою, сохранение ресурсов, предварительные усиления, зависимость от талантов, ручное AoE. Настройки, требующие недоступного API, помечаются «не поддерживается», а не имитируют работу.

**Будущий редактор приоритетов:** список правил с номером, заклинанием, условием, активностью, перемещением вверх/вниз, сбросом. В этапе 1 проектировать контракт и макет; движок исполнения и редактор произвольных условий — за пределами этапа.

## 1.7 Вкладка «Способности»
- Показывать только **текущий класс**, по возможности известные персонажу заклинания и доступные по талантам; ручного списка 9 классов нет.
- Поиск по названию/Spell ID; фильтры «Все», «Атакующие», «Защитные», «Утилити», при необходимости категории «кулдауны», «баффы», «контроль», «движение», «расы», «аксессуары», «питомцы/формы».
- Строка: иконка, название, категория, выучено/доступно, переключатель участия в рекомендациях.
- Карточка способности: Spell ID, доступность, категория, «разрешить рекомендации», «отображать отдельно», необязательная ручная *подпись* клавиши, восстановление значения по умолчанию.
- Хранение по CLASS/TREE/Spell ID, не по локализованному имени. При смене талантов список перечитать, настройки не уничтожать. Выключенная способность не передаётся в рекомендации после подключения движка.
- На этапе 1 допускается набор демонстрационных способностей с пометкой «тест», полный каталог — следующий этап.

## 1.8 Вкладка «Индикаторы»
1. Подсветка кнопок штатной action bar: вкл/выкл, рамка/свечение, цвет, интенсивность, только первая рекомендация или несколько разными цветами. Если кнопка не найдена, тихий отказ + диагностика. Учитывать сторонние панели только после проверки.
2. Защитная панель: вкл/выкл, 1–3 слота, размер, alpha, позиция/привязка, видимость в бою.
3. Прерывание: вкл/выкл, Spell ID, текст/звук, размер/позиция, состояния «рекомендовано», «недоступно», «непроверяемо».
4. Ресурс/здоровье игрока/цели/кастбар/GCD — запланированные виджеты, не показывать недостоверные значения.
5. Звуки: общий переключатель, триггеры важного действия/прерывания/защиты, настройка громкости только если разрешена, кнопка теста; ограничение частоты сигналов.
- Полное боевое поведение этих модулей — позже; в этапе 1 — визуальные компоненты и параметры, с правдивым состоянием поддержки.

## 1.9 Вкладка «Профили»
**Разделить сущности:** ротационный профиль (правила текущей CLASS/TREE) и профиль оформления (геометрия, видимость, цвета). Не смешивать.

**Хранение:** `KordRotationDB` для общих настроек, тем и наборов; `KordRotationCharDB` для привязки персонажа, последней подтверждённой ветки и персональных значений; настройки включения заклинаний и режима целей — по классу/ветке.

**Операции:** создать, переименовать, дублировать, применить, удалить с подтверждением, сбросить, скопировать доступный локальный профиль. Предустановки **Classic**, **Minimal**, **Compact**.

**Опция:** «Отдельный профиль интерфейса по специализации», по умолчанию ВЫКЛ. Она меняет оформление, а не автоматический выбор самой специализации.

## 1.11 Вкладка «Диагностика»
- Класс, уровень, ID/статус конфигурации талантов, очки в трёх ветках, выбранная ветка, способ и уверенность определения.
- Профиль CLASS/TREE, загружен ли; состояние UI, число иконок, координаты, масштаб, тестовый режим; последнее обновление и последняя ошибка.
- Проверка существования, успешности вызова и фактической доступности данных для `UnitClass`, `UnitLevel`, `C_ClassTalents`, `C_Traits`, `C_SpecializationInfo`, `C_Spell`, keybindings/action bar/events.
- Кольцевой буфер сообщений с временем, типом, модулем, диагностическим контекстом без бесконечного роста.
- «Скопировать» = открыть выделяемое поле для Ctrl+C, не утверждать программное копирование в буфер; «очистить», «повторить проверку талантов», «тест UI», «подробный лог».
- Ошибки не спамят боевой экран; различать недоступный API, отсутствие данных и ошибку Lua.

```text
      Indicators.lua Profiles.lua Advanced.lua Diagnostics.lua About.lua
  Data/
    Defaults.lua ClassSpecs.lua SpellCategories.lua
```
Это планируемая структура, а не утверждение о наличии файлов. Один источник правды для значений настроек и определённой специализации. `UI` только рисует; `Core` получает данные и уведомляет; будущий `RotationEngine` рассчитывает приоритеты.

## 1.14 Контракт ротационного движка с UI
Вход UI: `{ spec="ARMS", mode="single", recommendations={{spellID=12294}, {spellID=7384}, {spellID=5308}} }` — **демонстрационная схема**, не проверенная ротация. Отображение занимается текстурами, привязками клавиш, состояниями слотов, раскладкой и настройками. Оно не вычисляет следующий боевой приоритет. Отсутствие/недостоверность данных даёт «нет рекомендации», не выдуманный Spell ID.

## 1.15 Настройки, жизненный цикл и устойчивость
- Defaults -> проверка схемы/типа/диапазона -> пользовательские изменения -> уведомление подписанных UI-компонентов -> немедленное применение, если разрешено.
- SavedVariables сохраняются штатным жизненным циклом игры; не заявлять, что аддон самостоятельно записывает файлы на диск.
- Версия схемы, миграции, проверка повреждённых значений; безопасный fallback без удаления чужих параметров.
- После `/reload`, смены персонажа, ресайза/смены UI scale всё восстанавливается корректно; компоненты не плодят повторные обработчики.

## 1.16 Тест-план
| Кейс | Критерий |
|---|---|
| Установка/первый вход | Загружается без ошибок, defaults созданы |
| /kr и /kr config | Открывают/закрывают/переключают ожидаемые страницы |
| Девять классов | Класс определён правильно, нет ручного выбора |
| Каждая ветка талантов | Максимум вложенных очков определён верно |
| Равные/нулевые очки | Явный статус, предсказуемое правило |
| Перераспределение/набор | Обновление профиля после получения данных |
| Изменение 72->90 px | Немедленная перестройка UI |
| Количество 1–5/направления | Слоты не перепутаны и не перекрываются |
| Перетаскивание/lock/reset | Координаты ожидаемы и сохраняются |
| Видимость в/вне боя, цель, смерть, маунт | Соответствует приоритетам условий |
| Нет Spell ID/клавиши/API | UI не падает, диагноз понятен |
| Смена персонажа/спека | Изоляция данных, верный профиль |
| /reload, смена разрешения | Настройки сохранены, панель в пределах экрана |
| Ошибки и диагностика | Журнал воспроизводим и копируем вручную |

Для каждого теста в коммите/CHANGELOG: среда, шаги, ожидаемый и фактический результат, PASS/FAIL/NOT RUN. Только пользовательское подтверждение делает тест «прошёл на Forever».
