# Kord Rotation

**Текущий результат (2026-11-22): BM Hunter 1–59 перенесён в контрактный модуль целиком (SOURCE), но игровая проверка новой версии не выполнена.** По исходной стратегии v2.3 доступны все приоритеты, 22 настройки модуля, автоматический выбор по классу/дереву/уровню и полный журнал правил/провайдеров. Для уровня 60 зарегистрирован отдельный экспериментальный модуль с 26 настройками; рабочий прежний Arcane-пилот сохранён как изолированный fallback 61+. Историческое подтверждение в игре относится только к прежнему Arcane-пилоту, **не ко всей новой ротации**. Для неподтверждённых API движок сохраняет `UNKNOWN` и не выполняет кастов.

## Архитектура
- `KordRotation-user.zip`: один исходный каталог `KordRotation/`.
- `KordRotation-dev.zip`: те же файлы `KordRotation/` байт-в-байт плюс отдельный `KordRotationDevTools/`.
- Никаких автоматических кастов; DevTools записывает диагностику только после ручного «Начать запись».
- Журнал DevTools сохраняется **без Ctrl+C**: при заполнении буфера и при Stop/выходе из игры части записи попадают в `KordRotationDevToolsDB.sessions`. После `/reload` или выхода WoW сам создаёт/обновляет `WTF/Account/<ACCOUNT>/SavedVariables/KordRotationDevTools.lua`. Хранятся 12 последних частей по 512 записей, старые вытесняются. Отправлять можно сам сохранённый Lua-файл. Это не произвольная запись файлов из аддона.
- Полная стратегия `Kord_Hunter_BM_Leveling_PVE.lua` (v2.3) адаптирована в `Profiles/Hunter/BM_Leveling_Contract.lua` (Contract v1); при входе, получении уровня и обновлении книги заклинаний регистрируются `HUNTER_BM_LEVELING_PVE` (1–59) и отдельный `HUNTER_BM_60_PVE` (60). Неизвестные TTD, hawk count и другие непроверенные факты **явно видны как UNKNOWN**, а не угадываются. Детали — `docs/rotation/BM_Leveling_Integration_Status.md`.
- Во время записи DevTools через `CoreObservation.Audit()` исследует **весь активный профиль**: `RULE` по каждому приоритету, `SIGNAL` по каждому запрошенному бафу/дебафу/сигналу питомца, цели, ястребов, AoE и т. п., `STAGE` по шести этапам AbilityEligibility. `UNAVAILABLE/not_evaluated` означает, что этап не выполнялся. В журнале только допустимые коды причин и числовые приоритеты, без сырых игровых данных. Аудит не управляет боевой рекомендацией и работает только при ручной записи.
- Исторические Hunter-профили остаются исходниками в репозитории. Новый рабочий экспериментальный адаптер загружен в TOC; `docs/rotation/Profile_Contract.md` не изменялся. Неизученные способности, защищённые данные и неизвестные сигналы не считаются подтверждёнными.

## Как тестировать полный BM Hunter Leveling PvE 1–59 в WoW Forever

1. Скачайте [ZIP исходников текущей ветки main](https://github.com/Vi22Rus/Kord/archive/refs/heads/main.zip) и извлеките из архива каталог **`KordRotation`** в `World of Warcraft/_retail_/Interface/AddOns/` (используйте фактическую папку `Interface/AddOns` вашей установки Forever, она может отличаться). Папка должна содержать `KordRotation.toc` прямо внутри. Не копируйте весь каталог `Kord-main` как аддон.
2. В игре включите **Kord Rotation**, откройте **`/kr`**, вкладку настроек ротации. Включите рекомендации, выберите **одну цель / single** (не Auto) и отдельно включите **экспериментальные рекомендации**.
3. При входе с Hunter BM уровня 1–59 выбирается `HUNTER_BM_LEVELING_PVE`; с уровнем 60 — `HUNTER_BM_60_PVE`. На вкладке «Ротация» автоматически показываются настройки выбранного модуля. Для проверки всех правил установите отдельный DevTools, нажмите «Начать запись», сыграйте бой, затем «Стоп» и `/reload`.
4. Для диагностики можно отдельно установить `KordRotationDevTools`; он не требуется для пользовательской сборки. При неполадках экспериментальный режим можно отключить той же галочкой.

**Ограничение:** перенос всех правил и конфигов не означает, что все источники уже успешно отвечают в Forever. Мы намеренно тестируем полную ротацию сразу: отсутствующая классификация, отрицательная проверка аур, Summon Hawk, TTD, число целей, механика питомца и другие сигналы будут видны в `KordRotationDevToolsDB` как ошибки/UNKNOWN. Никакого автокаста. Для двух архивов из полного checkout используется `python3 scripts/build_variants.py`.
