# Kord Rotation — целевая матрица API и способы реализации

**Дата:** 2026-11-20. **Назначение:** архитектурная спецификация Kord Rotation на основе [сравнительной матрицы шести референсов](API_REFERENCE_MATRIX.md). Это наша отдельная таблица выбора реализации, **не отчёт о готовых игровых API**.

**Смысл статусов:** `CORE` — нужен движку; `CONDITIONAL` — включать при подтверждённой необходимости и наличии API; `DEFER` — пока не внедрять; `EXCLUDE` — запретить в движке без отдельного пересмотра. Приведённая «основа» — архитектурный ориентир среди референсов, а не копирование их кода. Имена методов и местоположения определены статическим анализом ZIP, не игровым тестом. Совместимость каждого метода с конкретным WoW Forever **NOT VERIFIED**.

## Выбранная архитектура

1. **GameAPI**: белый список read-only методов, вызов через `pcall`, проверка типов/конечных чисел и доступных проверок secret; `READY`, `UNKNOWN`, `UNAVAILABLE`, `ERROR` не смешивать. Проверка имени функции сама по себе не подтверждает качество данных.
2. **EventBus**: инвалидировать каналы по событиям, объединять дубли за 0.20 с; резервная проверка по 2-секундному heartbeat только подписанным потребителям. События и их аргументы сверять с конкретным билдом.
3. **Данные**: `GameState` отдельно от книги `SpellCatalogue`, панелей `ActionBarScanner`, клавиш `BindingResolver`, аур `AuraReader` и применимости `Eligibility`. Каждый адаптер возвращает источник, достоверность и актуальность.
4. **Ключевой фильтр**: изученный spell → подтверждённый **игровой action-слот Blizzard, отображаемый штатной или согласованной сторонней панелью** и активная страница/форма → подтверждённые условия применения. Кандидат без слота пропускается, проверяется следующий; если подходящих нет — `EMPTY`. Макросы/предметы не считать spell по одному имени.
5. **Бинды**: реальные `GetBindingKey` по binding-command слота; без бинда допускается подтверждённая иконка без подписи, но ручной `keyLabel` нельзя выдавать за автоматический.
6. **Безопасность**: никакого автокаста, RGB-кодировщика, пиксельных команд, `SendAddonMessage` для рекомендаций. Маскировка ID не гарантирует защиту от распознавания экрана.
7. **Референсы и лицензии**: Sonah, JustAC, MaxDps, ForeverAuras, ForeverRotation и RotationGuide используются только как ориентиры. Код не заимствовать без отдельной проверки лицензий.

## Решение заказчика по этапу 2.5 (2026-11-20)

**Разрешена поддержка штатных панелей Blizzard и сторонних интерфейсов Bartender4, Dominos, ElvUI, совместимых с уже загруженным LibActionButton.** Сторонняя кнопка допускается только если видна и однозначно сопоставляется с настоящим игровым action-слотом, подтверждённым `GetActionInfo`/`HasAction`; прямые macro/item/spell-кнопки без такого слота исключены. Никаких новых обязательных библиотек. Доказанное наличие в книге не снимает требования наличия слота. Реализация и неопределённости: [docs/STAGE_02_05_ACTIONBAR.md](docs/STAGE_02_05_ACTIONBAR.md). Реальный клиент и версии сторонних панелей не подтверждены.

## Приоритетные решения

| Подсистема | Основной метод и источник | Fallback и особенности |
|---|---|---|
| Слоты | `GetActionInfo`, `HasAction`; JustAC + MaxDps | `C_ActionBar.HasAction` (Sonah), проверить тип и страницу |
| Быстрый поиск | `C_ActionBar.FindSpellActionButtons` (Sonah) | Только ускорение, каждый slot перепроверить |
| Бинды | `GetBindingKey` (JustAC) | `GetBindingAction` для сверки |
| Книга | legacy `GetSpellBookItemInfo` (Kord + Sonah) | `C_SpellBook.GetSpellBookItemInfo` (RotationGuide), отдельная схема bank |
| Кулдауны | `C_Spell.GetSpellCooldown` (ForeverRotation) | legacy `GetSpellCooldown`, дополнительно slot cooldown |
| Ауры | `UnitAura` (ForeverAuras) | `C_UnitAuras.GetAuraDataByIndex` с проверкой структуры |
| Ресурсы | `UnitPowerType` → `UnitPower`/`UnitPowerMax` (MaxDps) | UNKNOWN при неверном типе/значении |
| Таланты | `C_ClassTalents` и `C_Traits` (существующий Kord) | legacy GetTalent* лишь после проверки клиента |

## Правила приёмки и дальнейшая работа

- **Сейчас документ, а не код.** Отложенные/условные методы могут перейти в CORE после проверки реального клиента и конкретного профиля.
- Записанные API в текущем `Core/GameAPI.lua` (2.2) не автоматически соответствуют окончательному списку. Новые allowlist-методы добавлять вместе с типовыми валидаторами и тестами. Для многозначных или struct API нужны индивидуальные нормализаторы.
- Неизвестное/защищённое значение не означает `false` или «всё готово». Различать отсутствие API, подтверждённое отсутствие действия и ошибки чтения.
- **2.3**: player/target/combat snapshot. **2.4**: книга и ранги. **2.5–2.6**: Blizzard slots и бинды. **2.7–2.8**: применимость и фильтр. **2.9–2.12**: отображение, анти-RGB аудит, диагностика и общий игровой QA.
- Если выбранный вариант требует API, отсутствующего в WoW Forever, реализовывать предусмотренный fallback либо блокировать соответствующее правило; не угадывать.
- Ячейки с файлами референсов — обзорные подсказки для проверки исходного кода, а не доказательство прямого исполнения. Для точного контекста обращаться к `API_REFERENCE_MATRIX.md`.
